## 本地预览

需要 `uv`（锁定 Python 3.12 依赖；桌面需要 Apple Silicon Mac）。从本项目根目录执行：

```sh
./scripts/dev.sh web
# 官网：http://127.0.0.1:8016/
```

开发验证码写入 `backend/.runtime/mail/`，不会发送真实邮件；可使用合成邮箱完成登录。真实支付及模拟付款默认均关闭。浏览器开启 14 天试用后，可在另一个终端启动源码桌面预览：

```sh
./scripts/dev.sh desktop
```

此命令为源码应用生成只含本地服务地址与公钥的配置，登录凭证仍保存到 macOS Keychain。会出现独立的 NetCare 图标，请避免与旧版同时执行网络修复。源码预览的数据在 `~/Library/Application Support/Relay/`；新目录首次建立时只复制旧配置，不覆盖原文件。`Ctrl+C` 结束前台官网服务；菜单“退出桌面”只结束界面，核心继续运行。停止核心请在设置中独立确认。

首次启用时网络守护默认关闭，完整检测等待手动触发；全新配置可能先进行本地只读环境识别。总览可明确启用守护，后续恢复新核心保存的选择，不自动采用旧菜单的守护开关。打开或重开窗口本身不触发检测。Agent 将健康目标、检测证据、问题事件、方案和验证结果组织成闭环，修改前需审阅方案与权限范围。未知状态不当作正常；关闭窗口或桌面不会终止核心，设置中的停止操作会先完成已有验证或回退。

切换检测预设后，未启用守护时等待手动检测，已启用时安排预算内的自动检查。主动修复所需的安全检查、修复后复检，以及主动“重新探测环境”仍会执行。账号权益同步与网络诊断独立，不触发网络检测。

默认首页优先展示保护目标、覆盖与新鲜度，技术检查按需展开；检测仍按序执行。处理记录、网络档案、权限与隐私、设置共用一个工作台。基础检测与报告不要求账号；历史报告不直接发起修改。

当前本地 Agent 已支持显式启用的 macOS 守护：网络配置变化通知触发检查，默认等待 5 秒稳定、持续抖动最多等待 30 秒，检查间隔至少 60 秒；正常时每 5 分钟检查，失败重试逐步退避至 30 分钟。每小时最多 12 次自动检查，次数跨重启保留；每次最多 60 秒、80 条检测命令、8 个 HTTP 访问请求，单响应体阈值 64 KiB（不是包含 TLS 和报头的总流量上限）。自动发现异常后在页面提供“查看方案”，同一事件不反复通知，修改仍需确认。暂停立即阻止新的守护探测，已启动的只读命令在自身超时内结束；已授权修复继续验证或回退。

模型调查已在独立核心接通工具循环，macOS 核心另有需独立确认的动态命令试用通道。源码和新构建 App 已默认使用 Agent 工作台，尚未替换已安装副本或完成签名发行验收。Mac 原生配置辅助服务已接入开发链路，但真实系统批准、root 运行和网络写入尚未验收；Windows 后续可选。账号、Keychain 与商业签名依赖缺失时，基础诊断与本地 Agent 仍可运行；自检会把这些能力列为可选项。macOS 变化订阅不可用时，界面明确显示“仅定时检查”。

主窗口与菜单中的“网络档案”支持建立、复制、修订、切换、移除，以及 JSON 导入/导出。每份档案最多 32 个 HTTP(S) 保护目标，可指定系统路径、不经应用代理、手工系统代理或已确认的 VPN 路径，指定全部环境或 VPN 连接/断开时适用，并分别要求网络可达或服务返回 HTTP 2xx。不经代理不代表绕过 VPN；服务探测不验证业务响应正文，不自动登录，也不跟随重定向。来源、版本、覆盖数量和最近验证分开显示。保存只修改 NetCare 的预期定义，不改系统配置；导入先进入草稿，不能导入授权、命令或已验证状态。

档案定义与观测独立存储。首次从现有访问目标建立档案，不把现场 DNS/代理故障学成正常配置；后续修订带版本冲突检查，保存与启用在同一事务内完成。检测结果绑定档案版本与目标定义，超过 10 分钟标记过期；仅新鲜且符合预期的检测更新最近验证。档案切换作废旧方案与结果。VPN 目标需具备既有的可信服务归属配置，逐目标核对目的路由、固定连接地址和接口、复核实际远端与路由；系统 PAC、代理例外或分接口规则尚不能验证时保留未知，不代用其他路径。DNS 查询仍由系统解析器完成，不能据此宣称 DNS 防泄漏或厂商全兼容。

档案保存于私有本地记录库，不重写旧配置中的目标列表。导出包含用户输入的原始地址，请仅分享给可信对象。当前守护仍受每轮 8 个 HTTP 请求等预算限制，大档案或慢响应可能导致未完成检测；跨轮目标轮换、企业策略编辑、复杂环境身份以及完整 Windows 路径适配仍待实现。

本地处理记录已持久化，工作台侧栏和菜单均可打开“处理记录”，无需账号。逐次确认绑定具体网络服务、目标值和现场证据，五分钟内仅可执行一次；过期、撤销、重复执行或目标变化都会阻止新的写入。重启后旧授权失效，中断的修改在下一次手动检测时只读核对，不重放命令。已结束记录默认最多保留 30 天、1000 条，未完成核对的任务不受该清理影响。原始恢复资料留在私有本地目录，普通记录窗口仅接收脱敏摘要；无法保存记录时修复暂停，守护不能新启动。

完整 Agent 蓝图的实施状态与验收证据见 [实施台账](docs/engineering/tickets/TKT-002-autonomous-agent-delivery.md)。当前源码通过的测试不代表完整自主 Agent 或新版安装包已经交付。

## Windows 与无界面核心

`code/relay_core.py` 可显式检查、管理档案及运行前台只读守护。该入口复用 Agent、档案和记录；窗口不是运行条件，账号和模型也不是前置依赖。macOS 新默认桌面已连接独立核心；开发机没有安装后台服务或特权执行器。

核心普通报告默认脱敏；原始证据仅在显式 `--raw` 或档案导出时输出。Windows 存储使用私有 DACL 和文件区间锁，不将 POSIX 权限位当成有效访问控制。具体启动、命令、数据目录及原生测试见 [Windows 只读预览](apps/windows/README.md)；契约见 [SPEC-002](docs/architecture/specs/SPEC-002-readonly-core.md)。目前仅模拟验证 Windows 行为，真实 Windows 尚未验收。

## 可选模型调查

`code/relay_core.py investigate` 默认仍只用本地能力。显式指定 `--model NAME --allow-model-upload` 才启用 Responses 模型；密钥从本机 `RELAY_MODEL_API_KEY` 环境读取，不能作为命令参数或档案字段。默认端点为 OpenAI Responses，也可显式指定兼容的 HTTPS 或字面量回环端点。本轮没有使用真实云端账号，尚无模型诊断质量或计费验收结论。

调查可记录假设、选择现有目标追加检查、修订判断、请求成熟修复方案及结束；恢复必须有新鲜全量实测验证。仅上传受限状态、目标别名、计数和授权执行后的有限收据摘要，不上传原始地址、配置或命令输出。上传同意不赋予写权限。macOS 模型可另外准备动态命令，但必须单独确认才能执行。CLI 的 `investigate --interactive` 和连接独立核心的源码桌面可在执行后继续同一调查，每个新方案仍需单独确认；跨核心重启的推理恢复尚未完成。

同一次调查（含授权后续接）默认最多 6 次模型调用，单次 20 秒和 1200 输出 token；与初始检测共用调查探测额度。等待确认/独立执行不消耗调查活动时间，但整次任务另受 15 分钟总时限约束。每数据目录每小时最多 12 次模型调用、保守预留 14400 输出 token，跨重启计数。模型受限会明确报告并保留既有本地能力；回退失败或未知副作用仍需核对，不能由模型文本解除。数据合同已更新为 v2，实际边界、费用说明和运行示例见 [SPEC-003](docs/architecture/specs/SPEC-003-reasoning-loop.md)。

## 动态命令试用

macOS 源码 CLI 的 `command FILE` 只准备完整私有方案，附加 `--interactive` 后仍需在真实终端输入完整方案哈希才能执行；模型方案可通过 `investigate --interactive` 走同一确认。动态内容不是固定工具清单，但也不是网络专用沙箱：可能访问用户文件、联网或调用已有权限辅助工具，不能依赖模型自报“只读”。默认不自动执行，不接收管道批准，不复用上传同意。

作业绑定命令内容、档案/现场、初始可执行文件哈希和调用身份，保存前置证据后启动。独立监督进程持有同用户写锁，管理超时、撤销和输出上限，并在核心异常退出后停止原进程组、保存终态收据；主动脱离进程组或委托外部服务的效果仍无法保证撤销。命令退出成功不代表网络恢复，未知效果须人工核对，不自动覆盖其他软件的新值。连接桌面的“处理记录”现可查看私有收据，填写核对说明并明确确认；CLI `review-command RUN_ID --interactive` 仍可独立使用，但须先正常停止占用同目录的核心。人工核对记为 `reviewed`，不是 `verified`。完整合同、入口和剩余风险见 [SPEC-004](docs/architecture/specs/SPEC-004-dynamic-jobs.md)。当前没有 Windows 动态执行、独立提权或通用回滚。

## 连接独立核心的桌面

macOS 源码模式可分别运行以下两个命令。核心启动不启用守护，首次新配置仍可能进行本地只读环境识别；桌面不创建另一个 Agent。退出桌面保留核心与任务，停止核心请在核心终端 Ctrl+C。不要与旧桌面共用正在占用的数据目录。

```sh
apps/macos/.venv/bin/python code/relay_core.py --data-dir "$HOME/Library/Application Support/Relay-core-preview" serve
apps/macos/.venv/bin/python code/relay_core.py --data-dir "$HOME/Library/Application Support/Relay-core-preview" desktop
```

源码/ad-hoc 开发包的私有 Unix socket 校验同一用户、本次核心实例和请求；动作需完整方案审阅与一次确认，超时只查询记录，不自动重发。该开发传输不是签名应用认证或特权通道，不能防御具有当前用户文件访问权限的恶意代码。Developer ID 构建使用同签名构建、用户与登录会话的 XPC，签名不符不会降级 socket；详细边界见 [SPEC-009](docs/architecture/specs/SPEC-009-signed-core-transport.md)。Windows 本地传输、真实签名服务、已安装版本升级和发布验收仍待完成。业务协议、操作去重及授权边界见 [SPEC-005](docs/architecture/specs/SPEC-005-local-core-ipc.md)。

连接菜单新增“设置”和“权限与隐私”。模型配置保存不等于上传同意；必须另行审阅当前接收地址和证据约定并确认。名称与地址存入私有配置，密钥仅留在本次核心内存，不写普通设置或操作日志；重启不恢复密钥或上传同意。换地址不能保留原密钥，可随时撤销上传或清除实例密钥。上传同意不赋予网络修改权限，也不会自动启动调查或守护。

“处理记录”支持最近 50 次的搜索、脱敏时间线和单独的全部待核对列表。设置可调整已结束任务保留为 7–90 天、100–1000 条（默认仍为 30 天、1000 条），在后续任务写入时清理；待核对任务、恢复材料和安全审计不随此设置删除。通知默认关闭，仅在该桌面运行且系统允许通知时发送新的待确认/待核对提醒。

连接模式现使用同一原生工作台承载总览、处理记录、网络档案、权限隐私和设置。总览优先显示保护目标、覆盖与新鲜度，再展开技术检查；导航不触发探测，切页保留档案草稿和编辑焦点。任务详情分为时间线、调查依据、修改回读，可打开脱敏任务报告。模型假设不冒充根因；成熟修复展示真实保存的原值、计划值及验证/回退回读，旧记录没有的数据不补造。动态输出仍仅在私有收据中查看。核心忙时仍能阅读已落盘记录及权限设置，关闭窗口不结束核心。760×560 深浅色实渲染已检查；完整无障碍、安装版迁移及跨平台验收仍未完成。

修改默认仍逐次确认。连接桌面可在成熟方案中显式选择本次任务信任（最多 15 分钟/3 批方案）或限定范围持续信任（当前核心内最多 8 小时/12 批）。它们绑定所审阅的字段、目标值、服务、档案和网络/VPN 环境；原值可以变化，范围不能自动扩大。调查或已启用守护在范围内自动处理，动态命令与超范围仍需参与；只读检测不变成自动写入。隐私页可独立撤销，下一写入停止，已写值仍需验证/回退。创建信任不启用守护或授予上传/管理员权限；桌面关闭不失效，核心重启后暂停。任意命令高信任、签名身份/提权及真实跨平台验收尚未完成。合同见 [SPEC-006](docs/architecture/specs/SPEC-006-scoped-repair-trust.md)。

## Agent 生命周期预览

也可用 `apps/macos/.venv/bin/python code/relay_app.py --agent-desktop --data-dir "$HOME/Library/Application Support/Relay-core-preview"` 打开并按需启动独立核心。退出桌面保留任务；设置页可显式停止核心，等待当前验证/回退及停机回执后才确认完成。已明确停止时，重新打开桌面不会自行启动，离线设置保留“启动核心”。只恢复用户明确保存的守护选择，不恢复修复信任、模型密钥或上传同意。

新构建 App 默认双击与 `code/network-doctor-menu.py` 默认运行均进入 Agent 工作台，也接受 `--agent-desktop`、`--core-service` 和 `--lifecycle`。显式 `--legacy-desktop` 保留旧菜单回退入口，不可与核心同时占用同一目录。macOS 13+ App 默认数据目录支持 SMAppService 登录服务适配、系统批准状态和保留数据的卸载准备；源码/自定义目录禁用注册。服务注销前必须先收尾，超时不强杀。真实注册/系统登录退出、Developer ID 签名安装和升级尚未验收，本轮只构建 ad-hoc 开发包，未替换安装副本。运行与边界见 [SPEC-007](docs/architecture/specs/SPEC-007-core-lifecycle.md)。

Developer ID 构建要求先由用户明确启用并批准登录服务，未完成时显示等待状态，不另起弱身份临时核心；macOS 12 和自定义数据目录不支持该签名模式。精确代码哈希拒绝旧构建连接，升级需匹配的旧客户端先安全收尾，自动更新尚未实现。源码/ad-hoc 的临时核心预览不受此注册前提影响；目前真实 XPC 测试使用同进程匿名 endpoint 和开发代码哈希，不代表正式签名安装通过。

系统配置修复另有独立开关和系统批准。签名 Core 的 DNS、IPv6/代理开关写入经同一受信任构建的原生辅助程序，不能传入任意 shell；没有 helper 不降级临时提权。设置可请求批准、核对激活和安全注销，变更后核心保持停止。中断后可从处理记录审阅原值/现值，明确恢复原值或保留现值并复验；不重放原方案、不覆盖第三方新配置，也不恢复旧授权。尚需受信任升级及真实系统验收，详见 [SPEC-011](docs/architecture/specs/SPEC-011-native-helper-service.md) 和 [SPEC-012](docs/architecture/specs/SPEC-012-helper-recovery.md)。开发机没有注册该服务或改动网络。

账号登录/取消/退出/同步及账户页已迁入设置，既有 Pro 历史、比较与诊断包在处理记录工具栏和菜单可用。账号与历史工作在独立可选队列，不授予核心修复权限或上传同意。继续复用原 Keychain 账号与 `history.sqlite3`，到期不删除已有历史；基础报告和 Agent 任务记录始终独立免费。Pro 快照只在桌面运行、观察到已提交结果且权益有效时记入；后台核心日志不是 Pro 历史，也不承诺补齐桌面关闭期间每次诊断。

设置中的检测预设与重新识别由核心串行执行，必须匹配当前配置版本；磁盘文件在核心启动后被外部改动时拒绝覆盖，需停止并重启核心后重新读取。修改会使旧修复权限失效、清空旧检测结果，但不重写健康档案目标、授予管理员权限或启用守护。详细迁移合同见 [SPEC-008](docs/architecture/specs/SPEC-008-default-agent-desktop.md)。

## 正式上线所需输入

需要确定域名、经营主体和客服邮箱，并提供独立生产 SMTP、PostgreSQL/TLS、支付商户与 Apple Developer ID/公证配置。生产模式缺少必要配置会拒绝启动。真实商户通知/退款、邮件送达、备份恢复、签名安装和第二台 Mac 兼容性必须完成预发布验证；目前不会把开发安装包标成正式下载。
