# PRD-002：自主网络保障 Agent

日期：2026-09-26。
状态：产品方向已由用户确认，并于 2026-09-27 授权按整体蓝图逐步实施。具体支持范围与验收证据见 [实施台账](../../engineering/tickets/TKT-002-autonomous-agent-delivery.md)。不是已完成功能清单。

## 1. 已确认的产品目标

NetCare 是一个自主网络保障 Agent：自动理解设备的网络环境，持续发现影响连接的问题，在用户授权范围内主动修复，并验证网络是否恢复到符合预期的健康状态。

用户启用软件的网络守护能力、完成必要授权后，不需要先描述问题，也不需要自行判断是网卡、VPN、DNS 或代理故障。Agent 应主动发现任务并完成处理，而不仅仅解释结果或让用户复制命令。

原平台愿景包括 Windows 和 macOS。2026-09-27 用户明确调整：当前先完成 Mac 完整可验收版本，Windows 后续可选，投入过高时可不做，不再阻塞本轮交付。目标环境仍包括有线、无线、热点、VPN、代理、公司网络及其复杂组合。目标是逐步扩大可识别、可诊断、可处理、可验证的范围，不是宣称任何故障都能自动修好。

## 2. Agent 的责任

1. 自动采集当前网络条件、配置及相关软件状态。
2. 结合网络健康档案，判断哪些连接能力应该可用。
3. 主动发现异常，提出假设并决定下一步检查。
4. 形成处理方案，主动请求所需授权。
5. 在授权范围内调用工具或生成并执行命令，直接修改需要修复的本地配置。
6. 根据真实结果继续诊断、验证恢复，必要时尝试回退或其他恢复措施。
7. 完成后回到守护状态；无法继续时明确原因和需要用户或管理员参与的事项。

成熟问题可以复用经过测试的修复工具；复杂问题允许 Agent 根据现场情况生成命令。产品方向不限定为只能从固定修复动作列表选择。执行仍应可追踪、可停止，并在可行时支持恢复。

## 3. 授权与交互

用户认可逐次授权以及充分信任后的较大权限模式作为可考虑的方向。逐步授权、本次任务授权、持续信任模式的默认值、范围、有效期和例外规则，仍需具体设计。

正常时低打扰；授权范围内可处理的问题自主处理。超出授权、需要身份认证、有明显中断风险或无法确认正确配置时，再请求参与。较高权限不意味着可以忽略公司策略，也不意味着系统允许访问任意受保护内容。

本次对产品方向的确认，不是授权开发过程直接修改当前电脑的网络配置，不代表当前运行版本已经取得持续监测或系统写入权限。

## 4. 健康与成功标准

健康不是所有网站都必须打开，而是该连通的资源能够连通，该保留的路径与安全策略没有被破坏。

- Agent 需要区分自动采集的现状与可信的预期配置；企业目标、管理策略等不能凭空猜测。
- 成功以原问题解除和保护目标未退化为依据，不以命令退出码或配置写入成功代替。
- 网络恢复与配置回退是不同结果；无法保证所有操作均可撤销。
- 外部停机、物理断线、账号权限等不能靠本机提权保证解决，需要正确定位与交接。
- 云端不可达时仍需要本地基础诊断和必要恢复能力；具体实现待设计。

## 5. 与现有版本的关系

当前实现已新增本地网络保障 Agent 核心，用于把健康目标、检测证据、处理事件、授权前方案、成熟修复工具和验证/回退结果组织为一条闭环。支持手动检测及用户显式启用的 macOS 守护，修改默认逐次确认，也可显式审阅成熟范围信任。macOS 源码核心已接通动态作业和同进程授权后调查续接；源码/新构建已默认进入独立核心工作台，Windows 目前只读，完整跨平台产品和独立特权执行器尚未完成。下文按实施先后保留阶段记录，完整当前状态以 TKT-002 为准。

2026-09-27 继续落实本地任务可靠性与守护：逐次确认生成绑定具体方案且限时的一次授权；修复前复核目标、配置和现场证据；任务与收据写入本地 SQLite；重启使旧授权失效并可只读核对中断任务。守护新增原生变化订阅、防抖、冷却、断网退避、跨重启资源预算和开关；异常方案在页面中等待确认。处理记录已接入原生窗口且不要求账号。完整跨平台守护、模型推理、动态命令和高信任执行仍属于实施范围，尚未完成。

同日新增网络健康档案的 macOS 本地流程：建立、复制、修订、切换、导入草稿与导出；每个保护目标独立声明 HTTP(S) 地址、访问路径、VPN 适用条件和成功标准。界面显示来源、版本、覆盖与最近验证；历史结果、用户预期与修复授权不混用。目标探测与成熟修复验证已接入该定义，服务认证/重定向、过期结果和未确认路径不会被当作服务恢复。企业管理策略、复杂环境身份、跨轮覆盖和完整 Windows 流程仍待实施，不能以此视为完整 F2 交付。

随后新增共享环境证据结构、Windows 只读采集、用户/会话作用域、原生变化订阅适配及无界面 CLI。档案、Agent、记录和守护预算可在该入口复用。Windows 写入、VPN 实际路径、桌面及安装服务均未完成；现有桌面也尚未与独立核心建立 IPC。新增 Windows 行为由模拟测试验证，真实 Windows 测试尚未执行。实现边界见 [SPEC-002](../../architecture/specs/SPEC-002-readonly-core.md)。

无界面核心进一步接通可选模型调查：显式上传同意、最小证据、假设与引用、指定现有目标追加复查、修订判断、准备成熟方案和结束前实测验证；记录/探测/模型预算及失败原因持续保留。模型不能自行授权，当前工具集不是产品永久限制。已用脚本化响应和真实回环 HTTP 验证协议与生命周期，没有云端诊断质量或 Windows 真机结论。运行与边界见 [SPEC-003](../../architecture/specs/SPEC-003-reasoning-loop.md)。

随后接通 macOS 动态命令交互试用：模型或用户可准备非预置命令，必须查看完整内容并单独确认；绑定调用身份、现场、内容哈希及有效期，监督进程处理超时/撤销/核心崩溃和终态收据。退出码不等于恢复，任意副作用保留人工核对，不自动运行回滚文本。该通道不是网络沙箱，不覆盖 Windows/提权/桌面视图。仅以临时文件作业和 FakeMac 网络验证，见 [SPEC-004](../../architecture/specs/SPEC-004-dynamic-jobs.md)。

同进程调查现可在用户授权执行后接收有限收据摘要、继续更新证据和判断；不上传原始命令输出，不重置调查预算，后续动作须再次确认。成熟修复回退失败及动态未知效果仍需核对，模型不能自行清除。核心退出后保存实际收据但不自动恢复推理。跨进程/重启续接、完整桌面入口、任务/持续信任和真实效果验收仍待落实。

macOS 后续新增 `serve` / `desktop` 源码连接模式：独立核心保留任务和调查，原生桌面通过同用户/实例校验的本地协议检测、管理档案、查看完整方案并逐次确认，断线不重发修改。关闭桌面不关闭核心。默认安装入口尚未迁移；当前身份校验不等于签名应用认证，Windows 传输、持久安装、特权服务和完整产品体验仍未完成。具体边界与运行见 [SPEC-005](../../architecture/specs/SPEC-005-local-core-ipc.md)。

连接模式进一步补充模型设置、独立的上传同意/撤销、内存密钥清除和隐私操作记录；保存配置本身不上传，不恢复旧同意。处理记录支持最近 50 次搜索与全部待核对列表，私有收据人工核对绑定具体哈希、档案与新鲜只读证据，结果不是自动验证。保留策略可调整，待核对任务不自动清除。

后续已统一五个主视图的原生导航，首页按保护目标呈现预期、覆盖、新鲜度与技术检查，任务详情连接时间线、模型假设/证据、工具阶段和成熟修改的真实回读。导航不探测、草稿/焦点保留、忙时读取记录和权限、760×560 深浅色已通过本地 IPC 与 Cocoa 联测。五视图全部产品契约、无障碍、系统安装/提权、高信任、Windows、真实模型质量及发布验收仍在完整目标中；这些源码检查不替代整体验收。

成熟修复现增加显式任务信任（15 分钟/3 批）与当前核心内持续范围信任（8 小时/12 批），默认仍逐次确认。所审阅字段、精确目标值、服务、档案及网络/VPN 上下文限制后续自动处理，撤销与逐写核对、额度预留、恢复异常暂停已接通调查和守护。原生界面可选范围、审阅和独立撤销；只读检测不因此写入，授权不启用守护或上传。核心重启不恢复可执行信任，任意动态命令、签名提权和真实跨平台高信任仍未完成。具体契约见 [SPEC-006](../../architecture/specs/SPEC-006-scoped-repair-trust.md)。

随后增加普通用户核心生命周期：显式 Agent 桌面入口可独立启动/重连，完整停机先撤销新动作、等待验证/回退、释放记录锁再交付停机回执；退出桌面不停止核心。已明确停止时普通重开不自启，只恢复用户明确的守护选择，不恢复模型同意或修复信任。macOS 13+ App 接入用户登录服务适配与保留数据的卸载准备；源码/自定义目录不可注册。实际冻结包临时空闲核心和模拟服务已验证，真实系统服务注册、签名安装/升级仍未验收，默认双击入口尚保留旧账号/历史桌面。契约见 [SPEC-007](../../architecture/specs/SPEC-007-core-lifecycle.md)，完整范围不因此缩减。

默认入口随后切换为五页 Agent 工作台，原账号/商业历史/比较/导出和检测预设已兼容接入。账号服务为可选桌面能力，不接触核心授权与模型同意；Agent 处理记录和基础报告免费，原 Pro SQLite 和 Keychain 协议保留。预设/重新识别由核心按修订处理，拒绝覆盖外部改动，不重写健康目标。保留显式旧菜单回退；新构建不替换已安装副本，真实升级/账号往返及整体发布未验收，详见 [SPEC-008](../../architecture/specs/SPEC-008-default-agent-desktop.md)。

此前按用户反馈取消定时检测，是当时交互要求的实现；本次确认将产品方向升级为启用守护后的自主运行。当前首次安装仍默认未启用；用户选择启用后，通过环境事件及预算内健康检查推进。具体默认预算见 README，需继续结合真机网络切换、供电及热点场景验证；尚不能将当前模拟通过视为跨平台长期运行验收。

## 6. 下一步需要明确

- 首批服务个人复杂办公网络，还是企业 IT 管理场景；此前“个人优先”仅为研究假设。
- 首批场景与支持矩阵：每种情况需要什么证据、允许怎样处理、如何验证。
- 授权模式：默认方式、持续信任的范围、风险升级和撤销行为。
- 跨平台观测、动态命令执行、审计、离线恢复及厂商适配的具体设计。
