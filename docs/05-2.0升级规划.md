# 05 2.0 系统性升级规划

> 版本：v2.0 正式版（在"菜单栏版 v2.0 初版"基线之上） ｜ 状态：规划稿，待确认后实施

## 1. 升级目标

把"能用"升级为"**好用、可靠、安全**"：

1. **可靠**：菜单栏图标一定能显示，且能自检；进程与自启状态单一可信；
2. **安全**：修复动作"场景感知 + 确认 + 可回滚"，绝不再出现非公司网络被切公司 DNS 导致失联；
3. **好用**：通知提醒、历史趋势、配置化、快速检测、清晰的报告界面。

## 2. 现状问题 → 2.0 方案映射

| # | 现状问题（见 03/04） | 2.0 方案 | 优先级 |
|---|---|---|---|
| 1 | 图标可能不显示，且无自检 | 启动自检（NSStatusBar 注册确认 + 兜底重试）；统一 launchd 入口 | P0 |
| 2 | 自动修复无场景感知（9-12 事故） | 场景识别（直连/VPN/ClashX）→ 修复前置确认 + 修复后自检 + 一键回滚 | P0 |
| 3 | 多启动入口、状态混乱 | 单一 launchd 管理；start 脚本只作状态查询/兜底；废弃旧 .app 入口 | P0 |
| 4 | DNS 混配等告警无通知 | 系统通知（问题出现/恢复） | P1 |
| 5 | 无历史记录、无趋势 | 本地历史库（JSONL）+ 最近 24h 趋势报告 | P1 |
| 6 | 配置硬编码 | 配置文件 `~/.config/network-doctor/config.json`（DNS、URL、间隔、开关） | P1 |

| 9 | 无打包发布链路 | py2app + 签名脚本 + README 安装向导（或 homebrew 风格安装） | P2 |

## 3. 架构升级设计

```
network-doctor/                        # 2.0 代码仓库（建议独立于归档目录）
├── network_doctor/
│   ├── __init__.py
│   ├── config.py        # 配置加载/默认值（config.json 可覆盖）
│   ├── checker.py       # 检测引擎（并行化、场景识别、规则表）
│   ├── fixer.py         # 修复引擎（确认、执行、自检、回滚）
│   ├── history.py       # 历史记录（JSONL 追加 + 汇总）
│   ├── notifier.py      # 系统通知（问题出现/恢复）
│   ├── ui.py            # rumps 菜单栏 UI（状态机驱动）
```

### 3.2 场景识别（核心新增）

在检测前先判定**当前场景**，所有规则与修复策略都以场景为上下文：

| 场景 | 判定 | 期望配置 |
|---|---|---|
| `direct` 直连国内 | VPN 未连 && ClashX 未跑 | DNS=公共、代理=关、IPv6=关 |
| `vpn` 公司 VPN | utun4 有 IP（VPN 已连） | DNS=仅公司、代理=关、IPv6=关 |
| `clashx` 仅代理 | ClashX 跑 && 端口监听 | DNS=公共、代理=开(指向7890)、IPv6=关 |
| `unknown` | 无法判定 | 只提示，不自动修复 |

**修复安全策略（P0 核心）**：
- 修改 DNS/代理前必须结合场景给出"当前 → 目标"预览并确认；
- 修复后 5 秒内自检（解析 3 个目标域名），失败自动回滚原配置；
- `--assume-yes`/无人值守模式默认禁止（除非显式配置）。

### 3.3 图标可靠性（P0）

- 启动序列：注册 NSStatusBar 图标 → 等待 2s → **自检**（询问 NSStatusBar 当前 items 是否包含本实例）；失败则重试 3 次 + 写日志；
- 统一入口：只有 launchd gui 域实例被认可为"主实例"；其他入口发现主实例存在即退出（防双图标）；
- 图标资源：用真实 icns 四态图标替代 emoji（emoji 在不同系统下渲染不一致）。

### 3.4 状态机

```
            ┌──────────┐
            ▼          │
   [init]──▶[checking]─┐
      │       │        │
      │       ▼        │
      │  [good/warning/error]──▶ 通知(状态变化) → 历史记录
      │       │
      └───────┘(每 30s 循环；手动检测随时触发)
```

- 状态变化（good→warning、warning→error 等）触发系统通知（P1）；
- 每次检测结果追加历史（P1）。

## 6. 验收标准（2.0 完成的定义）

1. **图标可靠**：连续 3 次冷启动（reboot）后菜单栏图标均出现，且日志记录自检通过；
2. **无失联事故**：非公司网络 + VPN 断开场景下，一键修复**不会**把 DNS 切成公司 DNS；任何修复动作失败都能自动回滚；
3. **状态单一**：任意时刻只有 1 个网络助手主进程；`pgrep -fl 网络助手` 与 launchd state 语义一致；
4. **通知与历史**：状态变化有系统通知；历史库记录每一次检测；
5. **配置化**：改 config.json 即可调整 DNS/URL/间隔，无需改代码；
6. **检测性能**：单次完整检测 ≤ 8s（并行化后）；
7. **回归**：核心场景（直连/VPN/ClashX/混配/残留）各 10 次检测，判定与修复符合规则表；
8. **安装向导**：新机器按 README 三步完成部署并自启。
