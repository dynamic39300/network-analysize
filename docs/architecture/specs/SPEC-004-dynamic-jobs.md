# SPEC-004：动态命令的授权与执行收据

2026-09-27。当前是 **macOS 源码核心的显式交互试用通道**，不是默认自动执行，也不是完整高信任模式。承接 [BLUEPRINT-001 §6.3–6.4](../BLUEPRINT-001-autonomous-network-agent.md)；动态命令不再限于预置修复列表，但现阶段每次执行必须单独确认，未知副作用必须人工核对。

## 实际入口

`DynamicCommands` 负责把动态内容装入现有 `ActionProposal`，复用限时授权、方案哈希、撤销与任务 journal。`jobs.py` 执行一个确定作业，不决定它是否获准。Core/CLI 是用户意图入口；模型可调用 `propose_command` 生成内容，不能调用授权、执行或人工核对接口。

命令定义是严格 JSON：

| 字段 | 当前合同 |
| --- | --- |
| `argv` | 1–64 个完整参数；首项为绝对可执行文件路径，不隐式调用 shell |
| `stdin` | 显式 UTF-8 输入，最多 32768 字符；需要脚本时可在此或 argv 中提供完整内联内容 |
| `purpose`、`expected_effect` | 提议者声明的目的与预期，分别最多 1000 字符；不是事实或安全证明 |
| `recovery_notes` | 最多 2000 字符的人工核对/恢复说明，不能为空；不是可自动运行的补偿脚本 |
| `target_ids` | 当前健康档案中的目标 ID，不能扩展档案或导入授权 |
| `timeout` | 1–30 秒的命令运行时限；另有写前/写后只读检查预算 |
| `output_limit` | stdout/stderr 合计捕获 1024–65536 字节，超限停止命令 |

文档总量最多 64 KiB，重复 JSON 字段、额外授权字段、不合法参数或档案外 ID 均拒绝。目标列表只是操作意图，**不是 OS 访问控制规则**。模型使用目标别名，核心映射为本地 ID；不会为生成命令而额外上传实际 URL、配置或原始输出。

## 确认与写前核对

方案绑定任务、完整 argv/stdin、当前 OS 用户/组/会话、可执行文件的真实路径/内容哈希/文件标识、工作目录、环境变量、时间/输出限制、目标与档案版本，以及当前已采集的网络配置/接口/VPN/路由证据。可执行文件首项拒绝相对路径、setuid/setgid、世界可写文件和超过 128 MiB 的文件。初始进程不能是 root 或 setuid 身份。

普通成熟修复的确认不能授权动态命令；必须额外确认 `acknowledge_unrestricted=True`。CLI 先显示完整私有方案和哈希，只有真实交互终端中输入完整 `EXECUTE <方案哈希>` 才执行；管道输入、仅有命令文件、模型声明“已批准”和默认 `command` 预览均不执行。五分钟授权、方案变化、撤销和一次消费语义沿用既有 Agent。

监督进程先取得同用户执行锁，核心随后重新采集完整目标与环境，核对配置/对象/档案/进程身份/二进制内容。保存原始前置快照、目标基线和启动意图后，才向监督进程发送启动信号。文件/配置变化、已有终态收据、记录失败或撤销会阻止启动。该核对是最近一次观测，不是与整个操作系统建立原子事务；核对后仍可能发生外部竞态。

工作目录是独立的私有作业目录。子命令不继承父进程完整环境，只获得固定 PATH、语言和指向私有目录的 HOME/TMPDIR；Relay 不注入模型 API 密钥。`shell=False` 只意味着不隐式解释参数；用户确认的 `/bin/sh -c ...` 等显式解释器仍能运行脚本。[Python subprocess](https://docs.python.org/3.12/library/subprocess.html)

## 监督与协调

独立 spawn 监督进程负责子命令、非阻塞 stdin/stdout/stderr、输出限额、截止时间和控制连接。核心退出/撤销或控制连接 EOF 会停止作业；监督进程持有写锁直到命令组收尾，因此核心崩溃本身不会提前释放该作业的锁。正常退出也清理仍在原进程组中的后台子进程。命令结果包含 PID、退出码、停止原因、时长、捕获字节数、截断状态和 stdout/stderr。

当前 POSIX 实现使用新会话/进程组和 `killpg`，不是内核沙箱，也不能保证已另建会话、委托外部服务或其他主动脱离进程组的工作被终止。[Python os.killpg](https://docs.python.org/3.12/library/os.html#os.killpg)

成熟 Agent 修复也接入同用户写锁，默认放在当前用户的 `Library/Application Support/Relay/execution/`，与具体核心数据目录分离。不同数据目录中的合作实例不会同时写入；这是当前用户内的协调，不是跨用户/管理员/厂商软件/旧版实例的设备级排他。未核对任务的持久阻止仍以当前记录库为范围，尚无跨记录库的全局恢复登记。直接调用底层 FixEngine 而绕过 Agent 也不属于该协调合同。独立特权服务仍需建立完整设备级协议。

## 收据与恢复

启动前的计划、授权依据、恢复说明和前置证据进入私有 SQLite。监督进程另以独占创建方式保存 `job-receipts/<job-id>.json`，写入并 fsync 文件及所在目录；不覆盖已有终态收据。核心来不及接收返回时，重启仍可读取该文件。文件缺失、部分写入、权限错误、超限或哈希不符会保持未确认，不猜测命令已成功；收据落盘失败也有明确标志。作业目录与终态文件的独立清理策略尚未交付。

命令启动后，无论退出码是否为 0，均进入 `needs_reconciliation`。核心执行只读后检，记录原问题是否仍在、原正常目标是否退化、档案是否变化以及当前健康状态，但 `command_effects_verified` 始终为 false：这些网络观测不足以证明任意脚本的所有效果。命令可能已经写入时，普通报告中的 `network_writes` 为 null（未知），不能填 0。默认报告不输出 argv、stdout、原始配置或恢复资料。

重启不重放命令，不运行模型提供的回滚文本，不因网络碰巧健康就解除未知写入阻止。`review-command` 显示私有终态收据，用户核对后输入 `REVIEW <收据哈希>` 并填写说明；系统再只读采集现场，将该次决策记为 `reviewed`，不是 `verified`。该接口只解除这条任务的阻止，其他未核对任务仍有效。执行后若需要继续修改，应重新制定和授权新方案。

## 风险边界

这不是“只允许影响网络”的执行沙箱。命令以当前用户启动，但仍可能访问该用户的文件、发送网络请求、启动其他程序，或调用系统已允许的权限辅助工具；不能仅靠检查初始可执行文件禁止其后代使用额外权限。环境变量过滤不等于阻止任意代码读取用户凭据。Relay 不提供管理员密码输入框，也不把初始普通身份宣称为全程强制权限隔离。

绑定的是完整内联内容和初始可执行文件，不是所有传递依赖、动态库、被读取的外部脚本、远端响应或软件更新。当前用户恶意进程、恶意已授权脚本与管理员不在私有权限位或合作锁能够抵御的范围内。无法理解全部内容及恢复边界时应拒绝确认。不要在 argv、stdin、目的描述或恢复说明中放置真实密码/令牌；这些原始内容会进入本地审计。

当前试用以逐次确认和事后核对换取未知命令的可用性，不能据此宣称已经实现蓝图要求的自动修复覆盖、高信任模式、严格资源沙箱或可靠通用回滚。授权后同进程模型现可接收有限收据摘要继续调查，但不上传原始 stdout/stderr、不解除未知效果阻止；续接合同见 [SPEC-003](SPEC-003-reasoning-loop.md)。结构化效果验证、人工核对后的继续推进、按风险分类的工具合同、提权服务、Windows 作业控制与真实网络场景验收仍待完成。

## CLI 使用

在仓库根目录，先用 `profiles export ID` 查看当前目标 ID，按上表建立自己的私有 JSON 命令定义。`command` 和 `investigate` 会探测当前档案目标，不会只做静态文本检查。下面是用户显式选择的入口，开发没有自动运行这些命令去修改本机网络：

```sh
# 仅准备完整方案，当前进程退出后该授权机会失效
apps/macos/.venv/bin/python code/relay_core.py command /absolute/path/command.json

# 重新检查、显示全部内容，然后等待独立终端确认
apps/macos/.venv/bin/python code/relay_core.py command /absolute/path/command.json --interactive

# 模型生成动态方案时，也必须在终端再次确认才能执行
apps/macos/.venv/bin/python code/relay_core.py investigate --model NAME --allow-model-upload --interactive

# 查看私有收据；第二条才允许明确记录人工核对
apps/macos/.venv/bin/python code/relay_core.py review-command RUN_ID
apps/macos/.venv/bin/python code/relay_core.py review-command RUN_ID --interactive
```

`command` 预览/执行返回 2，表示未执行或仍需参与，不把命令退出码映射成健康成功；`review-command` 的 0 仅表示人工核对记录已保存。`check`/`investigate` 的健康退出码语义不变。`--raw` 输出原始结果；完整方案和 `review-command` 本身就是显式的私有材料查看，不宜重定向到公开日志。当前 CLI 不支持无人值守批准或自动人工核对。

`investigate --interactive` 也可逐次确认成熟修复（`REPAIR <哈希>`），执行后继续同一模型调查；如果再出现另一方案，需要另一份确认。动态方案仍使用更强提示的 `EXECUTE <哈希>`。停在取消、模型受限或需要参与阶段时不会因目标恰好健康就返回调查成功；离线降级后确已完成验证的本地恢复仍可正常结束，并保留模型受限标记。

## 验证范围

macOS 后续新增源码连接桌面的完整方案审阅与独立风险确认，执行后的模型续接仍留在核心，见 [SPEC-005](SPEC-005-local-core-ipc.md)。它不是签名应用认证，不抵御具有同用户文件权限的恶意代码。动态收据现可在该桌面人工核对，绑定客户端、五分钟令牌、收据哈希与档案，需非空说明和明确勾选；核心持有执行锁重新只读核对。结果仍是人工 `reviewed` 而非自动 `verified`，不会自动恢复模型调查。独立 CLI 核对仍需先正常停止同目录核心。Windows、提权、结构化效果验证/补偿和完整产品仍未完成。

实际运行的测试命令仅访问临时目录并打印测试内容，所有网络状态来自 FakeMac。覆盖精确确认、伪造/过期/复用、命令/文件/现场变化、记录失败、取消、超时、输出限额、环境变量过滤、同用户跨核心写锁、真实核心进程死亡后子命令停止和收据保留、目标退化、重启不重放、损坏收据及人工核对不冒充自动验证。原有桌面与模型回归继续运行，结果见 [QA-002](../../quality/reports/QA-002-diagnostic-panel.md)。

没有对真实系统网络进行动态修改，没有 Windows 原生动态执行、安装包、权限服务、原生桌面确认视图或真实模型修复收益的验收结论。完整目标仍按 [TKT-002](../../engineering/tickets/TKT-002-autonomous-agent-delivery.md) 推进。
