## 生命周期与运行

`relay_core.py serve` 持有唯一 AgentStore、任务、调查上下文和守护调度。桌面只缓存状态并发送结构化请求，不打开 journal、不调用 OS 检测/写入工具。窗口关闭或桌面退出不停止核心，不重置预算，也不取消已经授权的执行。核心中的未确认方案仍有原五分钟有效期；重新连接必须重新获取具体方案的确认令牌。

核心启动不启用守护、不执行健康目标 HTTP 探测、不调用模型。首次创建配置仍沿用 ConfigManager 的本地只读接口/进程环境识别；不能将“未发起目标检查”理解为完全不读系统信息。守护需在连接桌面显式开启，本模式目前只在该核心进程内保留启用状态，未安装登录启动项，也不会因旧 `guard.enabled` 自动打开。模型可由启动参数显式指定，也可由连接桌面保存名称/地址及本次内存密钥；上传同意是另一项明确审阅，不随保存配置或重启自动授予。

源码试用需分别运行核心和桌面，例如在仓库根目录的两个终端中：

```sh
apps/macos/.venv/bin/python code/relay_core.py --data-dir "$HOME/Library/Application Support/Relay-core-preview" serve
apps/macos/.venv/bin/python code/relay_core.py --data-dir "$HOME/Library/Application Support/Relay-core-preview" desktop
```

这是用户自行启动的入口，开发验证没有运行这些命令去检查真实目标或修改当前电脑网络。两端必须指定同一个目录。目录使用私有权限，不能是链接叶节点；完整 socket 路径须短于 104 字节，超长明确拒绝。不要与旧桌面同时占用同一数据目录；记录锁拒绝第二个核心，程序不结束另一个应用。独立预览目录不会复制旧企业配置，需先核对保护目标和策略。原菜单栏入口仍保留兼容，默认安装版本未切换。

核心终端 Ctrl+C / SIGTERM 停止接收请求、撤销后续动作、暂停守护，等待已开始操作收尾后释放记录锁。它不是由桌面父进程托管的子任务。进程崩溃后按既有 journal 与动态监督收据核对，不恢复旧授权或自动上传模型历史。原始动态收据现可在连接桌面人工核对，不需停止核心。独立 CLI `review-command` 仍需先正常停止占用同一目录的核心。

## 通信与身份

当前仅提供 macOS Unix socket 产品入口，Linux peer credential 分支用于开发/测试兼容，不能宣称支持 Linux 产品。Windows 明确拒绝此传输，没有未校验 TCP 降级。

- `ipc/` 为当前用户私有目录；socket 和 `connection.json` 为 0600。核心先取得 `owner.lock`，才清理自己的旧端点并原子替换本次描述符。第二个实例不能删除正在使用的端点。普通用户运行，拒绝 root 或 setuid 身份。
- 双方通过系统取得对端有效 UID，并要求与当前用户一致。macOS 使用 `getpeereid`；它证明的是 socket 对端的有效用户身份，不是其可执行文件签名或用户是否刚点击按钮。[Apple getpeereid](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man3/getpeereid.3.html)
- 每次核心实例生成新的 256 位私有凭据和实例 ID。每条连接以随机挑战和 HMAC-SHA256 校验核心、请求和响应，角色标签分离；实例、挑战、请求 ID、客户端 ID、方法和参数纳入校验。旧核心的客户端必须重新连接。凭据不进入普通输出、请求正文、模型证据或操作表。
- 帧为 4 字节大端长度和 JSON，不使用 pickle。最多 1 MiB，每条连接一个请求；读取和发送共用 5 秒绝对时限，最多 8 条连接。重复 JSON 键、非有限数、非法版本、额外参数和未知方法拒绝，错误不回显系统异常内容。使用标准 socket API；超时不是终止已授权修复的依据。[Python socket](https://docs.python.org/3.12/library/socket.html)

**信任限制：同一用户和私有凭据不等于可信应用签名。** 其他可读取当前用户文件的进程、管理员以及已经获准的非沙箱动态代码，仍可能取得该用户能力。这一阶段不能防御恶意同用户代码伪装桌面，不应把它用于提权服务或称为软件来源认证。签名应用/audit token、Windows 用户/会话与命名管道、独立 OS 授权执行器仍待实现。动态命令风险合同不因增加 IPC 而变成沙箱。

## 方法与操作记录

| 方法 | 行为 |
| --- | --- |
| `status` / `operation` | 读取缓存状态或某个持久操作 ID；核心忙时仍可查询 |
| `records` | 最近 50 次脱敏时间线及全部未核对任务；缺失脱敏模块时仅状态和本地操作标识，不含原始事件 |
| `task_detail` | 按任务 ID 读取已落盘的脱敏假设、证据、工具阶段、结论与结构化配置回读；不读取原始输出或工具参数 |
| `profiles` / `profile_export` | 显式本地私有档案读取，不作为脱敏导出 |
| `check` / `investigate` / `propose` | 提交一个后台操作，返回操作 ID；不授予修改权限 |
| `review` / `confirm` | 取得完整具体方案和一次审阅令牌；独立确认后才能执行 |
| `confirm_trust` / `revoke_trust` | 显式选择核心派生的成熟修复范围，签发任务/当前核心持续信任；紧急撤销不等待执行门 |
| `guard` | 本核心进程的显式启用/暂停；不安装后台服务 |
| `cancel` | 停止后续任务动作、撤销旧确认、暂停守护；已写入结果仍须看收据 |
| `revoke_model` | 撤销本实例上传同意，不冒充撤回已发出的内容 |
| `settings` / `preferences_save` | 读取本地能力、隐私操作、设置版本；按版本保存保留策略与桌面通知偏好 |
| `model_configure` / `forget_credential` | 保存名称/地址及本次内存凭据；配置变化撤销旧上传同意；清除凭据不需等待调查结束 |
| `consent_review` / `confirm_consent` | 审阅当前模型、地址、证据约定；单独确认上传，不启动调查、守护或授予写权限 |
| `receipt_review` / `confirm_receipt` | 显式读取私有收据；动态待核对任务需说明、勾选、精确哈希及新鲜只读核对 |
| `profile_save` / `profile_activate` / `profile_remove` | 串行更新严格档案定义，作废旧授权；不写系统网络配置 |
| `detach` | 撤销该客户端尚未使用的审阅令牌，不结束核心任务 |

仅一项普通后台操作可活动；并发修改返回 busy，停止、撤销上传/范围信任及暂停守护不在诊断队列后等待。有效期内等待确认时不以新检查或档案修改替换该任务，守护暂缓下一轮；方案过期后撤销旧确认，已启用守护可重新检查，不因过期任务永久停止。`check` 在此入口使用 60 秒/80 命令/8 HTTP 调查预算且仍只读；中断恢复的只读回读沿用剩余额度。旧 CLI `check` 合同保持。成熟执行器的既有验证/回退限制独立。

`records`、`task_detail` 和 `settings` 可在执行门被检测占用时读取。它们使用已提交的数据库记录及受锁保护的模型状态，不访问正在变化的引擎对象，不触发额外 OS 探测；多个元数据查询不承诺全局原子快照。档案/具体方案/收据审阅仍需原执行门。任务详情是显式字段投影，不包含工具参数、完整 argv、stdout/stderr、人工核对说明或恢复文件路径；脱敏组件不可用时只保留最小状态。

接受操作前，在同一私有数据库中保存请求 ID、客户端/方法/参数摘要和状态，不保存密钥参数正文。相同 ID 与摘要返回原操作；内容改变则拒绝。执行结果写回；保存失败保留 unknown 并阻止后续修改。停止与撤销是例外的安全收缩：操作记录写失败也会执行撤销/清除，不因无法审计而继续上传，但会报告操作未能确认完成。重启将 accepted/running 请求标记 interrupted，不执行它。记录保留 30 天，最多 10000 条；满额拒绝新操作，不为了接受新请求先丢弃窗口内去重证据。这个去重保证不是无限期永久账本。

本地传输超时意味着结果可能未知，而不是“命令未执行”。桌面记录已发出的操作 ID，重连后只查询该 ID，绝不自动重发确认或其他变更。新核心没有的请求明确显示结果未确认；已接受但失败/中断的操作仍可查看。操作 completed 表示调用流程结束，网络是否恢复由报告、收据和待核对状态决定。

## 确认与桌面

审阅令牌绑定本次核心、客户端、实时任务、完整方案哈希与原有效期，一次消费；令牌不持久化。动态动作必须另行确认非沙箱风险。请求只携带标识/哈希，不能提交伪造 AgentRun、授权对象、快照或任意执行对象。Core 再走原有授权、写前核对、同用户写锁、验证与恢复。执行后如仍有有效模型上下文，继续同一调查；新方案需新的审阅和用户确认。

连接桌面以 `WorkspaceWindow` 承载总览、处理记录、网络档案、权限隐私和设置，原有页面控件复用同一窗口。菜单保留调查、查看方案、停止任务和撤销上传。完整方案在独立原生窗口展示，包含完整 actions/argv/stdin、影响与恢复资料定义、哈希和期限；为准确显示控制字符，详细 JSON 使用转义文本。动态确认需勾选风险项，确认不是默认回车操作。失联、核心改变、方案过期或执行开始后禁用旧确认。旧快照不会因断线显示为当前已验证状态，界面明确“连接已中断 / 结果待核对”。

原始本地状态、方案与收据是私有数据，记录/任务报告使用独立脱敏投影；不能将 IPC 的本地私有 JSON 当作可公开日志。动态 stdout/stderr 不进入普通状态或模型上传。五视图导航已贯通，但全部产品内容、无障碍全量检查、持久服务安装/退出卸载、跨平台桌面和打包更新仍未完成。

### 统一工作台与调查详情

默认内容尺寸 1060×700，最小 760×560，侧栏固定 144 像素；窄内容区的档案表单采用双列、记录页采用上下布局。使用既有 Logo、系统色与原生控件。导航本身不启动检测或守护，页面读取由连接客户端发出；迟到响应只更新对应页，不抢导航或覆盖脏档案。切页保留编辑字段焦点与草稿。断线或核心实例变化使读取缓存失效，未读页显示占位；关闭窗口清除未提交的密钥和上传审阅，保留核心生命周期。操作错误显示在有界页脚，不弹重复模态框。

总览首先呈现活动档案、逐目标状态、预期路径、覆盖数和观测时间，随后展示可展开的技术检查。未检测、过期、断线、部分覆盖不能冒充健康；恢复待核对或方案待确认优先呈现。模型不可用与网络目标异常分别说明。当前任务链接定位记录，无需重新探测。任务详情分为时间线、调查依据、修改回读三个标签，并支持同内容的脱敏报告。假设始终标记为模型假设；工具步骤只展示记录的状态，模型结论不替代实测。

成熟执行器使用原有写前保存、验证及回退读数，持久化 `changes`：字段/服务、`before`、`requested`、`after`、`after_known`、回读阶段和时间，不为报告追加 OS 命令。回退成功记录实际回读；回退失败清空可确认的最终值。比较原值/计划值发生在脱敏前，避免不同 IP 被遮盖后误判一致。旧收据缺失结构化值时明确无数据，不推断已改成功；动态任意副作用不因此变为已验证。恢复文件仍是私有材料，独立于报告保留。

## 模型、隐私与人工核对

默认逐次确认不变。连接模式现可从具体成熟方案选择任务或限定持续范围信任；范围外或动态命令仍需要参与。签发、额度、逐写验证、撤销、原生审阅和核心重启暂停合同见 [SPEC-006](SPEC-006-scoped-repair-trust.md)。`status` 的 `active_execution` 在可信自动执行期间提供实际阶段；权限、设置及记录在核心忙时仍可读取。此范围权限与下面的模型上传同意分别管理。

方案、收据和上传同意使用不同用途的一次审阅令牌，均绑定客户端与核心实例。同用途重新审阅会使该客户端的旧令牌失效，另一用途的审阅不覆盖现有方案。最多保留 32 个未过期令牌。收据与上传审阅有效五分钟，后台取得执行门后再次核对有效期。断开连接、配置变化、过期或开始操作后，界面禁用旧确认，服务端仍独立复核。

模型配置采用随机修订标识防止覆盖旧版本。地址仅支持既有 HTTPS / 字面量回环 Responses 契约。只有明确选择“保留同地址密钥”且地址完全相同时能沿用现有实例密钥；换地址需替换或清除。密钥不得出现在已知的名称/地址字段，保存仅持久化名称与地址。重启不恢复密钥或上传同意。核心撤销立即使在途传输的允许检查失败；清除实例密钥还使旧审阅失效。不会撤回已发送的数据、修改调用 shell 的环境变量，也不承诺 Python 内存、系统 swap 或子进程缓冲区的安全擦除；尚未集成安全凭据库存储。

上传同意绑定模型对象、名称、接收地址、`relay-minimal-evidence-v2`、修订及当前核心；与网络修改授权无关。配置保存、审阅或同意都不触发探测/模型调用。隐私日志只存时间、枚举动作和绑定哈希，最多 1000 条，界面展示最近 10 条。撤销与清除在调查忙时仍可执行；记录失败不撤销其实际禁止效果。

私有收据视图包含原始收据、历史动作与既有人工说明；详情 JSON 转义控制字符。成熟收据只读，不能通过此入口绕过成熟恢复判断。动态待核对收据另需 1–2000 字的非空说明及勾选；核心绑定精确收据哈希和当前档案，再取得同用户执行锁并做有预算的全量只读核对。收据/档案变化、取消、缺失新鲜现场或过期都会拒绝解除阻止。完成写入人工说明、当前证据和 `command_effects_verified=false`，结果是 `reviewed` 而非 `verified`；同步当前内存任务，避免后续保存覆盖人工核对。不会自动续接模型或执行新命令。

设置只接受保留天数 7–90、已结束记录上限 100–1000 和通知布尔值，版本不符拒绝覆盖。默认 30 天/1000 条，在后续任务保存时清理；未核对任务、恢复文件、IPC 去重和隐私审计独立保留。记录视图提供最近 50 次搜索及独立的全部待核对列表，旧的未核对任务不因不在最近列表而隐藏。通知默认关闭，仅桌面运行时针对新待确认/待核对状态提示，首次连接、忙状态、重复状态不通知；系统授权或源码运行环境可能阻止送达。签名更新与特权辅助进程仍未实现；新 Agent 入口的登录服务、离线生命周期设置与停机 `shutdown` 合同见 [SPEC-007](SPEC-007-core-lifecycle.md)，旧的仅连接入口不假装知道系统注册状态。

## 验证

真实 Unix socket 测试覆盖本机对端 UID、私有权限、错误凭据、重启、nonce/超限/重复键拒绝、第二个监听器不能删除端点、严格方法、操作去重、重复/异客户端/改内容/过期授权、档案漂移、写前日志失败、忙时取消和重连查询。实际 spawn 测试核心只使用 FakeMac，验证客户端退出后任务仍在，测试核心被杀后重启标记中断且旧请求不重放。Cocoa 测试实际连接该本地核心、渲染原生诊断和确认窗口，包含深浅色、760×560、长命令、风险勾选、取消和断线禁用。

测试没有修改本机网络、使用云端模型、启用用户守护、替换旧安装或发布新包。完整结果见 [QA-002](../../quality/reports/QA-002-diagnostic-panel.md)。
