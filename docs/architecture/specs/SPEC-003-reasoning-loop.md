# SPEC-003：有证据约束的模型调查循环

2026-09-27。记录当前源码行为，不替代 [BLUEPRINT-001](../BLUEPRINT-001-autonomous-network-agent.md) 的完整范围。实现位于 `model_transport.py`、`models.py`、`reasoning.py`，通过 `NetworkAssuranceAgent` 和 `CoreRuntime` 接入既有档案、平台检测、修复方案和私有任务记录。

## 已接通的流程

显式启动调查或前台守护后，先做本地检测。目标已经健康时不调用模型；需要调查时，一个主模型在同一任务内提出可检验假设、选择已有目标追加探测、修订假设、请求成熟修复方案或结束调查。模型响应不是最终健康结论，假设的 `supported` 也不等于已验证根因。

当前工具合同为 `relay-investigation-v2`；具备动态执行适配的 macOS 核心额外提供仅准备方案的工具：

| 工具 | 实际行为 | 权限边界 |
| --- | --- | --- |
| `record_hypothesis` | 建立/修订有证据引用的简短假设 | 固定为模型假设，不标记已验证根因 |
| `refresh_environment` | 重新读取环境并检查全部档案目标 | 沿用当前档案、路径与探测预算 |
| `probe_targets` | 在新鲜环境上下文中检查指定目标别名 | 仅可选当前档案的 `t1` 等别名，不接受新 URL |
| `propose_repair` | 全量复查后准备已有成熟修复方案 | 停在待授权；没有模型自授权或执行工具 |
| `finish` | 请求结束、用户参与或管理员参与 | 恢复必须有新鲜完整实测；刚完成的成熟验证可复用，未知副作用不能由模型解除 |
| `propose_command` | macOS 核心准备精确 argv/stdin 与人工恢复说明 | 只准备，不授权；后续独立终端确认与收据见 [SPEC-004](SPEC-004-dynamic-jobs.md) |

部分目标复查不更新整份档案的正常基线，未复查目标保持未知。工具结果中的证据编号必须存在，假设修订必须引用已存在的假设；重复调用 ID、未知工具、额外授权字段、无效参数或伪造引用均停止本轮，不宽松猜测模型意图。

每次上传前保留调用预算记录，每次工具执行前保留 `started` 记录，完成后写入结果。引用的证据是不可变的最小摘要，附采集时间、档案版本和当时快照摘要哈希；当前任务保存最新完整快照，但不是每次历史原始 OS 快照的档案库。重启将未完成调查标记中断/取消，不自动重放工具。任务、证据、假设与工具记录沿用既有私有存储和保留策略。

## 授权后续接

同一 Core 进程中的调查现在可停在 `waiting_authorization`，保留有界内存上下文。用户在终端逐次确认后，成熟修复或动态作业产生真实收据；调查进入 `awaiting_continuation`。`resume_investigation` 核对原方案哈希、已结束收据以及与持久记录一致的最新快照，再在同一个 AgentRun 中继续调用模型。未执行、伪造/变更记录、换模型/同意对象、同一交接重复使用都不能续接。

续接保留先前函数调用/输出、证据编号、假设与修订、重复调用 ID 集合、调用/工具/token 计数和剩余探测额度。每次最新证据更新当前可用的成熟修复工具选项，可对新发现问题制定方案，但第二个方案必须获得第二份具体授权。上一动作收据存入 `execution_history`，最新收据仍独立保留；取消新方案不会声称此前没有发生过修改。

刚完成的执行后快照若在 30 秒内、时间不早于该动作启动、档案绑定一致且与持久记录匹配，可直接成为新的最小证据。只有成熟执行器明确 `verified`、完整且无检查错误的快照，才可在其摘要哈希未变化且仍新鲜时支持恢复结论；否则重新全量检查。动态命令、回退失败或其他未确认结果始终保留 `needs_reconciliation`，模型可继续只读调查/说明，但不能通过 `finish resolved` 或另提命令解除阻止。

用户明确接管已结束守护检查中的方案时，后续调查由当前会话持有，触发来源记为 `guard_followup`；保留原预算和模型同意，不重新启用已暂停守护，也不把失效的守护 ticket 当作新授权。Core 接口、CLI 与后续 macOS 源码连接桌面可走此流程，默认安装桌面尚未迁移。

核心进程关闭、取消或新调查不复用旧的内存上下文；重启后保留已执行收据/恢复状态，将未完成的模型续接标记中断，不自动重新上传。macOS 源码连接桌面现可通过本地协议交接具体方案，模型上下文始终留在核心，桌面断线不丢任务，见 [SPEC-005](SPEC-005-local-core-ipc.md)。跨核心重启恢复推理、动态人工核对后的自动续接和任务/持续信任仍待实现。

## 模型与传输

使用 Responses 协议：严格函数工具、每次仅一个本地调用、不允许并行工具或托管工具。本地仍以 `jsonschema` 验证参数，不信任供应商仅声明严格模式。连续调用保留供应商返回的 reasoning 项及工具结果；不将 opaque reasoning 内容写入本地任务日志。协议依据为 [OpenAI Function Calling](https://developers.openai.com/api/docs/guides/function-calling)。这不代表所有“兼容”端点或模型都通过了本项目验收。

请求设置 `store:false`，但这不等于供应商零保留、零日志或零缓存承诺；具体数据控制仍取决于服务、账户与使用功能。[OpenAI Data Controls](https://developers.openai.com/api/docs/guides/your-data)

真实 HTTP 请求运行在可终止的独立 spawn 子进程中，父进程持续检查撤销和整体截止时间。超时、暂停、退出或撤销会结束请求进程；释放任务记录锁前等待调查线程收尾。连接使用 HTTPS 的系统证书校验，仅字面量回环 IP 允许 HTTP；不接受 URL 中的用户名、密码、查询参数或片段。拒绝重定向，不向另一目的地址转发授权头。请求不自动重试。

远程 HTTPS 使用标准用户/环境代理发现；已观测到未验证的 PAC、分作用域规则、代理例外、未知系统代理或 SOCKS 时，调查显示 `model_path_unverified` 并停止上传。没有承诺模型请求与特定应用/VPN 使用同一实际路径。回环端点不经过代理，但回环服务自身可能再转发到云端，不能仅凭地址认定数据不离机。

## 同意与数据

默认没有模型。启用需同时指定模型名与本次进程的上传同意；密钥存在本身不启用 AI。`ModelConsent` 绑定具体客户端实例、端点、模型和最小数据合同，可以撤销，不能从档案导入或由模型工具生成。更换端点或模型需建立新客户端与新同意。此同意只允许调查数据传输，不授予网络修改、管理员权限或任意文件读取。

当前 `relay-minimal-evidence-v2` 上传白名单包含：平台、健康状态、有限技术检查状态、目标别名/预期路径/HTTP 状态/传输与路径验证结果、来源不完整数量、接口和路由数量、成熟修复问题代码、VPN 归属是否确认、是否存在待核对恢复、是否为部分目标检查。授权执行后另含动作类别、枚举结果、是否需核对、受支持效果是否已验证；动态作业额外含枚举停止原因、退出码、捕获字节数和截断标志。没有命令输出正文。数据合同参与 ModelConsent 绑定；后续还含这些工具结果、模型自身生成的简短假设和协议连续性内容。

不上传实际 URL、内部域名、IP、接口名、SSID、SID、原始配置、HTTP 正文、命令输出、授权凭证或原始错误。外部名称中的提示注入不会作为指令进入模型；即使模型输出伪造授权，也无法通过本地工具合同。最小摘要仍可能揭示拓扑规模或异常状态，因此也需要上传同意，不称为完全匿名。

API 密钥只从本次进程环境读取，放入请求授权头，不放在命令行参数、模型正文或任务日志；供应商若回显已知密钥，拒绝该响应。环境变量并非硬件密钥库，同用户进程和管理员仍属于既有主机信任边界。云端请求可能产生费用，没有在本轮使用真实账号验证或计费。

## 预算与降级

- 默认同一次调查（含授权后续接）累计至多 6 次模型调用和 6 次工具执行，单调用最多 20 秒、1200 输出 token；活动推理政策时长 90 秒，同时受共用探测预算的剩余活动时长限制。
- Core 手动调查及默认守护共用从首次检测开始的 60 秒活动时间、80 条命令、8 次 HTTP 调查探测额度，不因追加工具或续接而重置。等待用户确认和独立执行阶段暂停调查活动计时；`wait_seconds` 包括这两段非调查耗时，`wall_seconds` 始终记录总经过时间。执行器自身的写前/写后检查和作业限制独立，不应将调查计数误当作整个任务的所有系统命令数。
- 整次任务另有 900 秒总时限，包含最初检测、等待与执行。到期阻止新授权、后续动作和模型调用，不能通过本地降级方案绕过；已发生修改仍按执行器规则完成必要核对/回退。模型 HTTP 与目标 HTTP 分别计数。
- 每个数据目录每小时至多 12 次模型调用，保守预留最多 14400 输出 token；调用前事务写入，跨重启仍有效。失败或无 usage 的调用不返还预留额度。
- 模型请求体最多 64 KiB、响应体最多 128 KiB；这不是 TLS、报头或链路总流量的硬上限。历史增长超限即停，不悄悄移除关键证据继续执行。
- 有效 usage 汇总为已报告 token；缺失时 `usage_known:false`，不能将计数当作完整费用。预留不是账单，也不是跨多个数据目录/账户的全局消费上限。
- 相同工具、参数与未变化结果重复出现时停止。模型离线、超时、拒绝、错误数据、预算不足、档案变化、撤销或记录失败均保留明确原因。

模型受限不抹去本地观测。在档案稳定、记录可用且非部分目标快照时，仍可形成既有成熟修复方案；不会因此获得新写权限，任务总时限结束后也不通过本地兜底继续创建方案。现有 Python Agent API 的显式用户授权和验证/回退链路继续可用。CLI 不提供通用 `authorize`/`execute`，`investigate --interactive` 逐次显示成熟修复或动态作业完整方案并获得独立确认。核心进程退出后的待授权方案不能直接重放，需重新核对并确认；源码桌面/核心同用户协议见 SPEC-005，签名应用和特权身份校验仍待实现。

## 运行入口

在仓库根目录使用已锁定环境。下列命令是用户选择运行的入口，不会随安装默认触发：

```sh
# 仅本地能力，不调用模型
apps/macos/.venv/bin/python code/relay_core.py investigate

# NAME 替换为用户账户已开通并确认协议兼容的模型
# 先通过本机安全方式设置 RELAY_MODEL_API_KEY，不将真实密钥写在命令参数或聊天中
apps/macos/.venv/bin/python code/relay_core.py investigate --model NAME --allow-model-upload

# 已由用户运行的回环 Responses 服务，也需要显式同意
apps/macos/.venv/bin/python code/relay_core.py investigate --model NAME --model-endpoint http://127.0.0.1:8080/v1/responses --allow-model-upload
```

Windows 使用相同参数，将 Python 路径换成 `apps/windows/.venv/Scripts/python.exe`。`watch` 支持同样的模型选项，只在显式启动的前台生命周期内调查异常，Ctrl+C 收尾，不安装服务。`--data-dir PATH` 是位于子命令之前的全局选项；同一个目录不允许同时被桌面或另一核心占用。新目录先检查/导入所需健康档案，避免将默认公网目标误认成企业保护目标。

默认报告仅输出调查状态/停止原因/计数；`investigate --raw` 会输出本地原始证据和模型假设，不应当作公开报告。退出码沿用 `check`：0 为实测健康且记录可用、无待核对恢复；2 为仍有未解决事项；1 为命令失败。模型调用结束本身不决定退出码为 0。
